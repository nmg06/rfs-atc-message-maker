# Revue produit et refonte — 7 octobre 2026

Branche : `feat/flightdeck-user-experience`. Public : joueurs de Real Flight
Simulator, novices GitHub comme pilotes réguliers, avec ou sans ATC.

## Constats avant modification

- La racine du site ouvre une copie ancienne du formulaire mobile, sous l’ancien
  nom. Aucun parcours clair pour choisir Windows/Android ou comprendre iPhone.
- Le prototype et l’application complète ne sont pas clairement distingués à
  l’entrée. Un visiteur peut croire que Flight Finder existe dans le navigateur.
- Le formulaire commence par les designs/emojis avant le trajet. Le premier
  écran est rempli de contrôles plutôt que d’une action facile à choisir.
- Android propose sept minuscules onglets ; la même page centrée gaspille
  l’espace PC. Les résultats ont quatre actions concurrentes par ligne.
- Recherche : longue liste de critères, état vide peu utile, pas de comparaison.
- Plusieurs labels/aperçus n’ont pas de nom accessible ; le chargement initial
  affiche un texte brut si le moteur échoue, sans bouton de reprise.

Audit par lecture des moteurs partagés, interface, stockage, scripts de build,
tests ; navigation du prototype dans le navigateur. Socle avant modification :
173 tests Windows, 32 tests Android et neuf parcours navigateur réussis.

## Choix

1. Une entrée publique éditoriale, légère, bilingue, avec installation guidée,
   état réel des plateformes, conservation du brouillon et contraste/focus.
2. Un espace de préparation responsive : trajet d’abord, actions contextuelles,
   navigation adaptée, filtres principaux courts et détails progressifs.
3. Comparer des résultats réels, sans fabriquer des durées, avions ou horaires.
4. Respect des données et de la logique Python ; aucun serveur, CDN, compte ou
   suivi ajouté. La version Windows PySide6 reste compatible.

Les artefacts de test restent temporaires. Cette branche ne publie aucune release
ni nouvelle version du site en production automatiquement. La vérification visuelle
mobile utilise un viewport Android ; elle ne remplace pas un téléphone physique.

## Réalisé le 8 octobre

- Accueil public entièrement repris : identité Flightdeck, parcours de découverte,
  installation par plateforme, questions courantes, français/anglais, clair/sombre,
  navigation clavier et reprise du brouillon web existant.
- Prototype web : trajet avant présentation du message, aperçu lisible,
  réglages secondaires repliables, labels associés et état de sauvegarde honnête.
- Android : préparation découpée en trajet/identité/détails, champs principaux
  sur toute la largeur d'un téléphone ; résumé cliquable, actions Finder/Fuel,
  quatre rubriques et un menu Outils. Tous les anciens écrans restent accessibles.
- Finder PC/Android : liste complète de 2 700 types locaux dès l'ouverture,
  recherche dans cette liste et sélection de plusieurs types avec retrait individuel.
  Les types sélectionnés sont combinés par OU, les autres filtres par ET.
  Le choix multiple remplace l'ancien critère d'avion unique. Les variantes
  RFS partageant un même code ICAO restent indissociables dans cette base.
- Android : suggestions de durée modifiables et comparaison de trois résultats
  observés, conservée après redémarrage et export/import. Les valeurs inconnues
  restent indiquées comme telles. Retrouver un trajet relance la base réelle.
- Satellite : le mode choisi ne dépend plus de l'arrivée des images ; les
  frontières ne masquent plus la couche. Le cache réutilise les images de moindre
  résolution pendant le zoom, avec requêtes bornées et réponses obsolètes ignorées.
  Windows charge également une base satellite grossière avant les détails.
- Retrait de la commande de répétition de la blague sur PC et Android.
  La première présentation reste conservée ; le tutoriel peut toujours être revu.
- Le mode clair/sombre Android s'applique avant la réponse du stockage. Sur les
  WebView récents, les lignes d'avions hors écran évitent un rendu complet inutile.
- Corrections trouvées pendant les essais : clics de navigation interceptés par
  l'habillage, lien de validation ciblant un bouton au lieu du champ, hauteur
  tactile du raccourci carburant, débordement sur 320 px et aide cachée.
- Export du site par liste de fichiers autorisés : la publication future ne
  copie plus tout le dépôt, ni les dossiers de profils, builds et clés.

## Vérifications locales

183 tests Windows, 34 tests du moteur Android, 11 parcours navigateur et un test
du rendu satellite réussis. Chaque parcours utilise un profil temporaire.
Le sélecteur défile à la molette ; les recherches proviennent du SQLite embarqué.
FR/EN, navigation retour, dernier caractère avant fermeture, comparaison et
sauvegarde portable sont vérifiés. Largeurs testées : 320, 390, 768 et 1366 px.
Les opérations principales et le site font zéro requête distante dans ces essais.

Build Android debug et APK de tests compilés ; vérification des ressources
effectivement incluses, des permissions et du SHA-256 de la base de 138 Mo.
Build PyInstaller Windows et lancement du véritable EXE réussis : Finder
historique/récent, Fuel 12 285 kg, carte locale et guide de 30 questions.
Les journaux détaillés sont dans `build/ux-*` et ne sont pas publiés.

## Limites et suite

La nouvelle interface doit encore être essayée sur téléphone physique, notamment
clavier, rotation, grandes polices et appareils peu puissants. Les téléchargements
restent des builds de test, pas une release officielle signée. Une connexion
reste nécessaire pour de nouvelles images satellite et prévisions de vent ;
leur vitesse dépend des fournisseurs. Le cache mémoire ne promet pas un atlas
satellite hors ligne après fermeture.

La comparaison visuelle est présente sur Android, pas dans l'interface PySide6
ou le prototype web. Le site public explique cette différence. Le prototype web
n'a toujours pas le Finder SQLite. iPhone et synchronisation automatique restent
non portés ; les sauvegardes PC/Android se transfèrent manuellement.

Prochaine priorité : essais physiques et agrandissement des polices, puis
comparaison native Windows et réduction du coût de rendu des très grandes listes.
Les horaires actuels, les portes et les pistes assignées ne sont jamais déduits.
